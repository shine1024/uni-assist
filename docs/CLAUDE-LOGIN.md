# Claude 로그인 인증 — 설계 (v0.8.0, 2026-11-13)

claude.ai(팀플랜) 로그인 때 오는 **보안 링크 메일**을 슬랙 DM 에서 찾아, 링크가 보여주는 인증 코드를
로그인 화면에 자동으로 넣는 기능. 「유니클라우드 2차 인증」의 슬랙 연결(`lib/slack-otp.js`)을 그대로 쓴다.

> 상태: **구현 완료 · 실제 크롬에서 로그인 확인 (v0.8.0, 2026-11-13).** 아래 「확인 상태」.

## 확인된 사실 (사용자 확인, 2026-11-13)

| 항목 | 값 |
|---|---|
| 계정 메일 | 회사 메일 `unipost_sw_ai@unipost.co.kr` → 슬랙 DM 으로 전달 (유니클라우드와 같은 경로) |
| 메일 제목 | `Claude의 보안 링크가 도착했습니다` |
| 보낸 주소 | `no-reply-{임의값}@mail.anthropic.com` |
| 메일 버튼 | 「로그인」 → `https://claude.ai/magic-link#{토큰}` (토큰이 `#` 뒤 → 서버로 안 가고 페이지 JS 가 읽음) |
| 링크를 열면 | 같은 크롬에서 열어도 **코드가 보이는 페이지**가 뜸. 코드 위치: `.data-link-code` |
| 로그인 화면 | `[data-step="code"][data-active]` 단계, 입력칸 `input#code`(`data-testid="code"`, 숫자), 확인 `button[data-testid="continue"]` |

## 아직 모름 (구현 중 확인)

- 링크가 **일회용**인지 (확장이 열면 사람이 다시 못 쓸 수 있음 → 실패 시 「다시 보내기」 안내)
- 코드 **자릿수** (입력칸이 `inputmode="numeric"` → 숫자로 가정, 자릿수는 4~10 으로 넓게 받음)
- 슬랙 미리보기에 링크 주소가 남는지 → 안 남는다고 보고 **원본 메일 파일의 `body-html`** 에서 꺼냄
- 로그인 화면의 정확한 주소 (`claude.ai/login` 으로 추정) → 주소 대신 위 DOM 으로 감지

## 흐름

```
[claude.ai 로그인 탭] 이메일 입력 → 코드 입력 단계 표시
   │ content/claude-login.js : input#code 가 보이면 시작 (자동 입력 켰을 때만 심김)
   ▼
[서비스 워커] 슬랙 DM 조회 — 3초마다, 최대 3분
   │ 제목 「Claude의 보안 링크가 도착했습니다」, 시작 시각 이후, 아직 안 쓴 메일
   │ 원본 body-html → &amp; 디코딩 → https://claude.ai/magic-link#… 추출
   ▼
[서비스 워커] 링크 검사: https + 호스트 정확히 claude.ai + 경로 /magic-link
   ▼
[링크 탭] chrome.tabs.create({ url, active:true })  ← 숨긴 탭은 화면을 안 그려서 잠깐 앞으로 띄움 (D4 변경)
   │ scripting.executeScript 로 그 탭에서만 .data-link-code 를 최대 15초 기다려 읽음
   │ 읽은 값이 숫자 4~10자리인지 확인 → 탭 닫기 (실패해도 닫음)
   ▼
[서비스 워커] 메일 ts 를 「사용함」으로 기록 → 코드만 로그인 탭에 전달
   ▼
[claude.ai 로그인 탭] input#code 에 입력 → 「이메일 주소 확인」 클릭
```

사이드 패널에서는 「인증 코드 가져오기」 버튼으로 같은 과정을 돌리고 **복사 / 현재 탭에 입력**을 고를 수 있다
(유니클라우드 카드와 같은 모양).

## 보안

| # | 내용 |
|---|---|
| S1 | 보안 링크는 **서비스 워커 메모리에서만** 다루고 저장·로그·오류 메시지에 넣지 않는다. 로그인 탭(콘텐츠 스크립트)에도 링크는 보내지 않고 **코드만** 보낸다 |
| S2 | 링크는 `https://claude.ai/magic-link#…` 일 때만 연다 (호스트·경로·포트·사용자 정보 검사). 보낸 주소는 회사 메일 전달로 바뀔 수 있어 **막는 데 쓰지 않고 진단에만** 표시 |
| S3 | 코드 읽기 스크립트는 확장이 **직접 연 그 탭 id** 에만 넣는다. 읽은 뒤 탭을 바로 닫는다 |
| S4 | 같은 메일 재사용 방지 — 쓴 메일의 ts 기록 (유니클라우드와 같은 방식, 별도 키) |
| S5 | 자동 입력은 **켰을 때만**, `https://claude.ai/*` 에만 동적 등록 |
| S6 | 슬랙 토큰은 지금처럼 서비스 워커·패널에서만 |

## 동작 세부

- 링크는 **열기 전에** 메일을 「사용함」(`ua_claude_login.lastUsedTs`)으로 표시한다. 일회용 링크일 수 있어서, 읽기에 실패해도 같은 링크를 다시 열지 않는다
  → 실패하면 「다시 보내기」 안내.
- 패널과 자동 입력이 동시에 물으면 링크는 **한 번만** 열고 같은 결과를 둘 다 받는다(`inflight`).
- 링크 탭: 로그인 탭 옆에 앞으로 띄워(`active:true`) 열고, 문서가 `https://claude.ai/` 에서 다 불러와질 때까지 기다린 뒤
  `.data-link-code` 가 나타날 때까지 최대 20초 기다린다. 읽은 뒤에도 탭 주소가 claude.ai 인지 다시 확인한다. 끝나면(실패해도) 닫는다.
- 자동 입력 스크립트는 한 번 끝난(성공·실패·시간 초과) 입력칸에는 다시 시작하지 않는다. 코드 단계가 사라졌다 다시 보이면 새로 시작.
- 자동 입력을 켜면 이미 열린 claude.ai 탭에도 바로 심는다.

## 2026-11-13 수정 — "메일은 있는데 코드를 못 가져옴"

원인 후보를 모두 고치고, 어디서 멈췄는지 볼 수 있는 진단을 넣었다.
- 메일은 찾았는데 링크를 못 꺼내면 3분 기다리지 않고 바로 `CLAUDE_LINK_NOT_FOUND` 로 알린다 (전에는 "메일 기다리는 중"처럼 보였음)
- 보낸 사람 검사로 메일을 버리지 않는다 (전달 메일·슬랙 `from: [{address}]` 형식에서 막힐 수 있었음)
- 링크 후보: 원본 다운로드 → `simplified_html` → `plain_text` 순 (미리보기 `preview*` 는 잘릴 수 있어 제외).
  원본이 MIME 이면 quoted-printable(줄 끝 `=` 끊김, `=3D`)·base64 를 풀고, JSON 이면 필드 이름과 관계없이 모든 글자 값을 본다
- 링크 페이지 코드 선택자: `.data-link-code, [data-link-code]`
- 패널 「진단」: 최근 30분 메일 파일(제목·제목 일치·사용함 여부·보낸 도메인·본문 후보별 길이/`magic-link` 언급 수/링크 수/MIME 여부)과
  마지막 시도 단계(`storage.session` `ua_claude_last`). **링크·코드·본문은 넣지 않는다.** 「사용 기록 지우기」로 이미 쓴 메일 다시 시도

## 2026-11-13 수정 — 링크를 열면 바로 로그인됨 (실제 확인)

- 진단: 숨긴 탭에서는 링크 페이지가 화면을 그리지 않음(`visibility: hidden`, 본문 7자) → **D4 변경**: 링크 탭을 잠깐 앞으로 띄우고 끝나면 원래 탭으로 돌아감
- 앞으로 띄우니 **같은 브라우저라 링크가 코드를 보여주지 않고 바로 로그인시킴**. 로그인 화면 탭은 저절로 넘어가지 않아 새로고침이 필요했음
- 그래서 링크 탭을 0.4초마다 보며 먼저 오는 쪽을 처리한다
  - 탭이 `/magic-link` → claude.ai 의 다른 화면(`/login`·`/logout` 제외)으로 넘어감 → **로그인됨**: 0.8초 두고 탭 닫기 → 로그인 화면 탭(과 원래 보던 claude.ai 탭) 새로고침 → 패널 「보안 링크로 로그인했어요」
  - `.data-link-code` 에 코드가 보임 → 예전처럼 코드 표시·입력 (다른 브라우저처럼 동작할 때 대비)
- 패널 남은 시간은 1초마다 갱신 (전에는 조회할 때만 바뀌어 링크를 여는 동안 멈춰 있었음)
