### 자동 로그인 (v0.3.0 신규 — 코드 레벨 완성)
- 사이드 패널 **메뉴 3탭**: 🔤 텍스트 추출 / 🔐 자동 로그인 / ⚙ 설정

- **`F2`** → **로그아웃 요소가 있으면 로그아웃**, 없으면 복호화 → 값 주입 → 버튼 클릭
  - **로그인은 origin+경로 엄격 매칭 / 로그아웃은 origin 만** (로그인 후 다른 경로로 이동하기 때문)
  - 로그아웃은 복호화가 없어 **잠금 상태에서도 동작**. 사이트별 `autoLogout` 스위치 + 로그아웃 셀렉터
  - `matchPath` 는 기본 꺼짐(도메인 전체). 켜져 있어 로그인이 막히면 `PATH_MISMATCH` 로 원인 안내
- **`F4`** → 사이드 패널 열기/닫기 (닫기는 Chrome 141+ 필요)
- 전역 `auto-login`(기본 Ctrl+Shift+L) — commands API. `F2`/`F4` 단독은 commands 로 등록 불가해서 페이지 내 리스너를 씀
  - 리스너 등록 범위 기본 **모든 http(s) 페이지**, 설정에서 "등록 사이트만"으로 좁힐 수 있음
- 계정 2개 이상이면 **항상 선택창**(Enter/숫자키/↑↓/ESC). 기본 계정은 맨 앞 정렬+포커스만 담당
- 보안: PBKDF2-SHA256 60만회 + AES-256-GCM(고유 IV), 마스터 비번 미저장, 잠금 키는 `storage.session`,
  기본 1시간 자동 잠금(1·4·8시간), 수동 잠금, 마스터 변경 시 전체 재암호화
- 동기화: `storage.sync` 사이트당 1항목 분할 저장 + 사용량 표시 + 다른 기기 변경 감지
- 동기화 경합 가드(`ERR_SYNC_PENDING`) + 암호문 키 지문(`kf`)으로 원인 구분
- 테스트 신규 179종 (`test-login` 57 + `test-vault` 62 + `test-hotkey` 60) → 전체 **197종** (`node tools/test-all.mjs`)

### 2. 이후 개선 (기존 백로그 유지)
1. 선택한 요소를 패널에서 **호버하면 페이지에서 하이라이트** 되돌려주는 기능(역방향 강조)
2. 규칙 **드래그 앤 드롭 정렬** (현재는 ↑/↓ 버튼)
3. 프리셋/허용패턴 **내보내기·가져오기(JSON)** — 민감정보 포함 내보내기는 범위 제외
4. 추출 결과 **히스토리**(최근 복사한 결과 N개) 보관
5. (단축키) 사이트별로 **다른 프리셋 자동 적용** 검토
6. (로그인) 로그인 성공/실패 자동 판정(URL 변화 감지) 검토

## 🧠 메모 / 결정사항 (왜 이렇게 했는지)
- UI 형태: **사이드 패널** 채택 (팝업은 페이지 클릭 시 닫혀 요소 선택 워크플로와 안 맞음).
- 콘텐츠 스크립트는 매니페스트 상시 주입이 아니라 **필요 시 `chrome.scripting`으로 주입**(중복 주입 가드 `window.__uaPickerLoaded`).
- 셀렉터는 id 우선 → `tag:nth-of-type()` 경로. 같은 셀렉터에 여러 개 매칭 시 `index`로 구분.
- 변환은 규칙당 **순서 있는 단계 배열**(리터럴/정규식 혼용). 잘못된 정규식은 결과 대신 에러 메시지 표시.
- `chrome://`, 웹스토어 등 주입 불가 페이지는 토스트로 안내하고 동작 막음.
- 단축키는 `commands` API(전역) + **URL 패턴 게이트**로 "특정 사이트 전용"을 구현(`src/lib/match.js`). 허용 패턴은 `storage.local.allowedPatterns`.
- 서비스 워커는 클립보드 직접 접근이 안 되므로 **offscreen 문서 + textarea/execCommand** 로 복사(크롬 공식 패턴).

### 자동 로그인 (v0.3.0)
- **느슨한 패턴 매칭을 쓰지 않음**: 복사 단축키는 `match.js`(접두어+와일드카드)로 충분하지만, 로그인은 자격증명을
  주입하므로 `login-match.js` 로 **origin 완전 일치 + 경로 경계 일치**를 따로 구현했다.
- **마스터 비밀번호는 저장하지 않는다.** 알려진 평문(`uni-assist-vault-v1`)을 암호화한 검증자의 복호화 성공 여부로만 확인.
- **잠금 키 보관 위치**: MV3 서비스 워커는 유휴 시 종료되므로 전역 변수로 유지 불가 →
  `chrome.storage.session`(인메모리·디스크 미기록·콘텐츠 스크립트 접근 불가·동기화 제외)에 raw 키를 둔다.
  트레이드오프를 감수한 선택이며, IndexedDB(디스크 영속)는 "암호화 키 영구 저장 금지" 때문에 쓰지 않았다.
- **자동 잠금에 `alarms` 권한을 쓰지 않음** → 접근 시점에 만료를 지연 평가(권한 최소화).
- **계정 선택 UI를 페이지 안에 띄운다**(사이드 패널이 아니라). 사용자가 보고 있는 화면이기 때문.
  단, 페이지 JS에 노출되므로 **라벨 또는 마스킹된 아이디만** 넣는다. 마스터 비밀번호는 절대 페이지에 넣지 않는다.
- **React 대응**: `el.value = x` 는 React가 무시할 수 있어 `HTMLInputElement.prototype.value` 의 네이티브 setter로
  대입한 뒤 `input`/`change`(bubbles) 를 발생시킨다.
- **sync 분할 저장**: 항목당 8KB 제한(공식 문서 확인) 때문에 사이트당 1항목. 덤으로 다른 PC와의 충돌 범위가 사이트 단위로 좁아진다.
- `picker.js` 의 셀렉터 생성에 **안정 속성 우선** 단계를 추가했다(id → name/data-*/autocomplete/aria-label/placeholder/type).
  기존에 저장된 셀렉터는 그대로 쓰이므로 회귀 위험은 낮지만, 새로 선택하면 결과가 달라진다.
- `input[type=password]` 의 값은 `extractValue` 에서 항상 빈 문자열로 처리한다(텍스트 추출이 평문 비밀번호를
  `storage.local` 에 저장하는 경로를 막기 위함).

### 매칭 범위 · 금고 안전장치 (v0.4.1)
- **로그인과 로그아웃의 매칭 범위를 분리했다.** 로그인은 경로를 구분해야 하지만(같은 도메인에 앱이 여러 개),
  로그아웃은 로그인 후 이동한 아무 경로에서나 누른다. 같은 기준을 쓰면 로그아웃이 영구히 불가능해진다.
  로그아웃은 복호화를 하지 않으므로 origin 일치만으로도 자격증명 유출 위험이 없다는 점이 근거.
- **`matchPath` 를 자동으로 켜지 않는다.** 로그인 페이지 URL 로 등록하면 경로가 `/login` 에 묶여
  로그인 직후부터 매칭이 깨진다. 켜고 싶으면 URL 을 앱 루트로 고쳐야 한다 — UI 에서 경고한다.
- **조용히 실패하지 않게** 했다. origin 은 맞는데 경로 때문에 막혔으면 `PATH_MISMATCH` 로 원인과 해결책을 말한다.
- **동기화 경합이 데이터 손실을 만들 수 있다.** sync 는 키별로 도착하고 순서를 보장하지 않으므로,
  사이트만 먼저 온 상태에서 "최초 설정"을 하면 금고를 덮어써 기존 암호문을 잃는다 → `hasAnyLoginData()` 로 차단.
- **키 지문(`kf`)** 은 보안이 아니라 **진단**을 위한 것. `verifier` 가 이미 동기화되므로 추가 노출은 없다.
  지문이 없는 예전 레코드는 판단을 보류해 하위 호환을 지킨다.

### 로그아웃 · 패널 토글 · 계정 선택 (v0.4.0)
- **다중 계정이 못 쓰이던 결함**: `defaultAccountId` 가 있으면 선택창을 건너뛰어 2번째 이후 계정을 쓸 수 없었다.
  첫 계정 추가 시 자동으로 기본값이 되므로 **사실상 항상** 그 상태였다.
  → 기본 계정은 **맨 앞 정렬 + 포커스**만. 2개 이상이면 항상 선택창. Enter 한 번이면 되므로 체감 비용은 키 하나.
- **로그인/로그아웃 판별을 DOM 존재로** 한다(`sel.logout` 요소가 있으면 로그인 상태).
  표시 여부(`offsetParent` 등)를 보지 않는 이유: 로그아웃 링크는 드롭다운 안에 숨어 있는 경우가 많고,
  숨은 `<a>` 도 JS 클릭으로 동작한다. 대신 "로그인했을 때만 생기는 요소"를 고르라고 UI에서 안내한다.
- **로그아웃은 잠금 해제가 필요 없다**(복호화가 없음) → 잠금 체크보다 **앞에** 둔다.
- **패널 토글이 가장 까다로웠다.** `sidePanel.open()` 은 사용자 제스처를 요구하고 제스처는 `await` 에서 사라진다.
  열림 여부를 묻는 API 도 없는데 `storage` 조회(비동기)를 끼우면 제스처가 날아간다.
  → 패널이 유지하는 **포트**로 열림 상태를 메모리에 두고 **동기적으로** open/close 호출.
  `close()` 는 Chrome 141+ 라 미지원 버전은 안내로 대체.
- 단축키 리스너 범위 기본값을 **모든 http(s) 페이지**로 올렸다. F4(패널)는 어디서든 쓰는 기능이라
  "등록 사이트만"으로 두면 반쪽짜리가 되기 때문. 좁히고 싶으면 설정에서 끈다(그럼 F2/F4 둘 다 좁아진다).

### 페이지 내 단축키 (v0.3.1)
- Chrome `commands` 는 `Ctrl`/`Alt` 필수 + `F1~F12` 미지원(공식 문서) → **F2 는 commands 로 등록 불가**.
  그래서 `chrome.scripting.registerContentScripts()` 로 등록 사이트에만 리스너를 심는 방식을 택했다.
- 전역 단축키를 **없애지 않고 둘 다 유지**했다. 페이지 내 단축키는 주소창에 포커스가 있으면 못 받기 때문.
- 키 조합은 `"F2"`, `"Alt+Shift+L"` 처럼 **수정자 순서를 고정한 문자열 1개**로 저장한다(비교가 문자열 동등 비교로 끝남).
- 콘텐츠 스크립트가 ES 모듈이 아니어서 함수 3개를 복제했다. 대신 테스트가 파일에서 그 구간을 꺼내
  lib 와 같은 입력으로 비교하므로, 한쪽만 고치면 CI(=`test-all`)에서 걸린다.
- 콘텐츠 스크립트는 `storage.sync` 를 직접 읽는다(콘텐츠 스크립트도 `storage` 접근 가능). 메시징 왕복을 줄이기 위함.
  `storage.session` 은 콘텐츠 스크립트에서 접근 불가라 애초에 쓸 수 없다.
