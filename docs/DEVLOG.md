## 2026-10-31  v0.4.1 — 로그아웃이 "등록되지 않은 사이트"로 막히던 버그 + 금고 안전장치
- **[버그 수정] 로그아웃 시 "등록된 사이트가 아니에요"**
  - 원인: 로그인 페이지 URL(`.../redmine/login`)로 등록하면 `matchPath` 가 **자동으로 켜져** 경로가 로그인 페이지에 고정됐다.
    로그인 후 `/redmine/my/page` 로 이동하면 경로 불일치로 매칭 자체가 실패 → 로그아웃 불가.
  - 수정 ①: **로그아웃은 origin(프로토콜+도메인+포트)만 일치하면 동작**한다(`findOriginMatchingSites`).
    로그인은 경로를 구분해야 하므로 엄격 매칭을 유지. 로그아웃은 복호화도 하지 않으므로 자격증명 유출 위험이 없다.
  - 수정 ②: 사이트 추가 시 **`matchPath` 를 자동으로 켜지 않는다**(도메인 전체가 기본). 필요하면 사용자가 켠다.
  - 수정 ③: origin 은 맞지만 경로 때문에 로그인이 막힌 경우 `PATH_MISMATCH` 로 **원인과 해결 방법을 안내**
    (토스트 + 패널의 현재 탭 안내 + 체크박스 경고). 켜져 있으면 "로그아웃은 경로 무관"임도 함께 표시.
- **[안전장치] 동기화 경합으로 저장된 비밀번호를 영구히 잃는 문제**
  - 원인: Chrome sync 는 키별로 따로 도착하고 순서를 보장하지 않는다. 사이트는 왔는데 `ua_vault` 가 아직
    안 온 순간에 "최초 설정"을 하면 새 salt/verifier 로 덮어써서 기존 암호문을 열 수 없게 된다(last-write-wins).
  - 수정: `hasAnyLoginData()` 로 그 상태를 감지해 **최초 설정을 차단**하고 "동기화 중" 안내(`ERR_SYNC_PENDING`)
  - 최초 설정 화면에 "다른 PC에서 이미 설정했다면 그 비밀번호를 입력하세요" 경고 추가
- **[진단] 키 지문(`kf`)** — 암호문마다 키의 SHA-256 앞 6바이트를 함께 기록.
  복호화 실패 시 "손상"과 **"다른 마스터 비밀번호로 암호화됨"(`KEY_MISMATCH`)** 을 구분해 안내한다.
  지문 없는 예전 레코드는 판단을 보류하므로 기존 데이터와 호환된다.
  보안: `ua_vault.verifier` 가 이미 동기화되고 있어 추가로 노출되는 것은 없다(실제 방어선은 PBKDF2 60만회).
- 테스트: `test-login` 41→57종(키 지문·origin 매칭), `test-vault` 53→62종(동기화 경합 가드) → **총 197종 통과**

## 2026-10-31  v0.4.0 — 로그아웃 · 패널 토글(F4) · 계정 선택 결함 수정
- **[결함 수정] 다중 계정이 사실상 못 쓰이던 문제**: `defaultAccountId` 가 있으면 선택창을 건너뛰어
  2번째 이후 계정을 쓸 방법이 없었다(첫 계정 추가 시 자동으로 기본값이 되므로 항상 그 상태).
  → 기본 계정은 **선택창에서 맨 앞 정렬 + 포커스**만 담당하도록 변경. 계정이 2개 이상이면 **항상 선택창**을 띄운다.
  라벨도 "기본" → "먼저" 로 바꿔 의미를 맞췄다.
- 계정 선택창에 **키보드 조작** 추가: `Enter`(포커스된 계정) · `숫자키` 바로 선택 · `↑↓` 이동 · `ESC` 취소. 항목에 번호 표시
- **로그아웃 기능** (같은 `F2`): 사이트별 **로그아웃 셀렉터**를 등록하면,
  그 요소가 페이지에 있으면 로그인 상태로 보고 로그아웃을, 없으면 자동 로그인을 실행한다
  - 로그아웃은 복호화가 필요 없으므로 **잠금 상태에서도 동작**
  - 드롭다운 안에 숨은 로그아웃 링크도 다루기 위해 **표시 여부는 보지 않고 DOM 존재만** 확인
  - 사이트별 `autoLogout` 스위치, 셀렉터가 비면 자동으로 꺼짐
- **사이드 패널 열기/닫기 단축키 `F4`** 추가
  - `chrome.sidePanel.open()` 은 **사용자 제스처**를 요구하고 제스처는 **`await` 를 만나면 사라진다**(공식 문서 + 확인)
    → 서비스 워커 메시지 핸들러에서 **동기적으로** 호출. 열림 여부도 storage 조회 없이 메모리 집합으로 즉시 판단
  - 열림 상태는 패널이 유지하는 **포트**(`runtime.connect`)로 추적. 포트가 연결된 동안 SW 가 살아 있어 신뢰 가능하고,
    SW 가 죽었다면 집합이 비는데 그때는 패널도 닫힌 상태. 패널 쪽은 포트가 끊기면 재연결
  - `chrome.sidePanel.close()` 는 **Chrome 141+** 전용 → 미지원 버전에서는 열기만 되고 안내 메시지 표시
- 단축키 리스너 등록 범위 기본값을 **모든 http(s) 페이지**로 변경 (패널 토글을 어디서든 쓰기 위함).
  설정의 **모든 사이트에서 사용** 을 끄면 기존처럼 등록된 로그인 사이트에만 심는다
- 설정 → 단축키 카드를 2개 행(로그인/로그아웃, 패널)으로 재구성 + 각각 키 지정·On/Off, 충돌 경고
- 실행 후보 선정 로직을 순수 함수로 분리(`accountCandidates`, `logoutCandidates`) → 테스트 가능
- 테스트: `test-hotkey` 40→60종, `test-vault` 42→53종 (설정 병합·신규 사이트 기본값) → **총 172종 통과**
- 권한 추가 없음

## 2026-10-31  v0.3.1 — 페이지 내 단축키 (F2 지원)
- **배경**: Chrome `commands` API 는 단축키에 `Ctrl`/`Alt` 를 반드시 포함해야 하고 지원 키 목록에 `F1`~`F12` 가 없다(공식 문서 확인).
  → `F2` 단독 키는 `chrome://extensions/shortcuts` 에서도 등록 불가
- 해결: `chrome.scripting.registerContentScripts()` 로 **자동 로그인이 켜진 사이트의 origin/경로에만**
  키 리스너(`src/content/hotkey.js`)를 동적 등록. 사이트/설정 변경 시 자동 재등록(`storage.onChanged`)
- 기본 키 **F2**, 설정 → 단축키에서 **키 지정**(키 캡처) / 사용 On·Off 가능. 기존 전역 단축키 `Ctrl+Shift+L` 도 그대로 유지
- 수정자 없는 일반 글자키를 지정한 경우 **입력창 포커스 시에는 무시**(글자 입력 보호). `F2` 등 기능키는 입력창에서도 동작
- 키 조합은 `"F2"`, `"Alt+Shift+L"` 같은 **정규화 문자열 1개**로 저장(`src/lib/hotkey.js`) → 비교/저장 단순화
- 매치 패턴에 포트가 거부되는 환경을 대비해 포트 없는 패턴으로 **재시도 fallback** (실제 포트 검증은 `siteMatches` 가 담당)
- 콘텐츠 스크립트는 ES 모듈이 아니라 `comboFromEvent`/`isTypingTarget`/`needsTypingGuard` 를 복제했고,
  **복제본이 lib 와 갈라지면 테스트가 실패**하도록 동기화 검사를 넣었다(실제로 드리프트를 잡는지 확인함)
- 테스트 `tools/test-hotkey.mjs` 40종 추가 → **총 141종 통과**
- 권한 추가 없음 (`scripting` + 기존 `host_permissions` 로 충분)

## 2026-10-31  v0.3.0 — 자동 로그인 관리 기능 추가
- 사이드 패널을 **메뉴 3탭**(텍스트 추출 / 자동 로그인 / 설정)으로 재구성. 기존 추출 UI 마크업·로직은 그대로 유지
- 신규 단축키 `auto-login`(기본 `Ctrl+Shift+L`) → 등록 사이트에서 ID/PW 입력 + 로그인 버튼 클릭까지 자동 실행
- 다중 사이트·다중 계정 등록, 기본 계정 지정, 후보가 둘 이상이면 **페이지 내 계정 선택 오버레이**
- 매칭은 origin(프로토콜+도메인+**포트**) 완전 일치 + 경로 경계 일치 (`src/lib/login-match.js`)
- 보안: PBKDF2-SHA256 60만회 + **AES-256-GCM**(레코드별 고유 IV), 마스터 비밀번호 미저장(검증자 방식),
  잠금 해제 키는 `chrome.storage.session`(인메모리·동기화 제외), 기본 30분 자동 잠금(접근 시점 지연 평가)
- HTTPS→HTTP 다운그레이드 차단, 최상위 프레임에만 주입, 주입 후 `location.origin` 재확인
- PC 간 동기화: `chrome.storage.sync` 에 **사이트당 1항목**으로 분할 저장(항목 8KB·전체 100KB 제한 대응) + 사용량 표시
- 마스터 비밀번호 변경 시 저장된 모든 비밀번호를 **한 번의 set 호출로 재암호화**
- `picker.js` 개선: `id`·`name`·`data-*` 등 **문서 내 유일한 안정 속성을 최우선**으로 셀렉터 생성 (로그인 입력창에 유효)
- `picker.js` 보안 수정: `input[type=password]` 의 값은 추출/전달하지 않음 (평문 저장 경로 차단)

  `test-all.mjs` 러너 추가 (기존 18종 유지 → **총 101종 통과**)
- **권한 추가 없음** (기존 storage/scripting/tabs/activeTab/host_permissions 로 구현)
